logits = dotproduct(emb1, emb2)
scaled_logits = logits/temperature

loss uses softwmax(scaled_logits)

let logit1 = 1
let logit2 = -1

let x1 = logit1/temperature
let x2 = logit2/temperature

p1 = exp(x1)/(exp(x1) + exp(x2))
p2 = exp(x2)/(exp(x1) + exp(x2)) 
   
no scaling, temperature=1:
p1 = 0.88
p2 = 0.12

scaling: temperature=0.1  makes distribution more peaked, pushes logits further apart
helping to learn the tail and diversity for example.
p1 = 0.9999546021312976
p2 = 2.06e-9
from: p=np.exp(1/T)/(np.exp(1/T) + 2047);
This low temperature regieme can  also can akso lead to instability when 
FalseNegatives are in the negatives.
the False NEgative will have a high probabiliy like the positive does
p=np.exp(1/T)/(np.exp(1/T) + np.exp(1/T) + 2046); p
=0.4778085963226425
   and gradient scales with that probability.
the gradient of the positive is hence decreased by the false negative(s).
and the next time that same positive is seen perhaps there are 0 false
negatives.  that variance in the positive's gradient is larger for
temperature 0.1 than it is for temperature 0.25, making the lower
temperature less stable.

scaling temperature=10 makes a flatter more uniform distribution
p1 = 0.55
p2 = 0.45

to learn the hard negatives, we want a more peaked dist so we divide
by a number between roughly 0.05 and 0.15 or so.
if the distribution is made too peaked, then the model only learns the
peak and the model collapses due to:
- in the 1000s of negatives in a batch, there will likely be a few that
  are actually ones that the user liked and it will penalize those by
  making them all like the negatives. anything that is not the positive
  is pure negative if distr is too peaked.
- can cause loss collapse to NANs if the temperature is too small, i.e. < 0.01
- 1 positive nearly equal to 1 and all else are negatives nearly 0 means
  the gradients will have large zig-zag variance while trying to push
  pairs apart.

the temperature scaling should be applied in train and eval
step, but is not necessary in the model call because
the values of the scored list are relative.   the scaling
can be applied or not in the model call.
