Training the TwoTowerDNN with an in-batch softmax loss, lr-scheduler and Adamw optimizer,
and using the metric composite_ndcg@100 on the validation set for early stopping,
minimum threshold, and model selection by the keras tuner BayesianOptimization.

** see the analysis in docs/mlops/best_fitting_model_stats/twotowderdnn_softmax/
   including the train, val, test curves

exeuction times:
- running the pipeline with BayesianOptimization and 6 parameters that have range
  or choices takes 5-7 hours
- running the piepline with RandomSearch an all fixed parameters takes 1 hour.

When reading the metrics in docs/mlops/best_fitting_model_stats/twotowderdnn_softmax
keep in mind these statistics for random:
------------------------
random recall@k ~ k/movie_catalog_size
random ndcg@k ~ (1/movie_catalog_size) * sum_{i=1,100}( 1/(log_2(i+1) )
random mrr@k : single relevant item in catalog:
               = (1/movie_catalog_size) * sum_{i=1,100}( 1/i )
random precision@k : single relevant item in catalog:
               = ((k/movie_catalog_size) * (1/k)) + ( ((movie_catalog_size-k)/movie_catalog_size) * 0  )
               = 1 / movie_catalog_size

Note that random precision and mrr are better calculated by using retrieval
within the catalog for each user.

The metrics are above expectations for random selection.

Embeddings and the t-SNE, UMAP plots:
   the user and candidate embeddings made from these trained models
   were plotted use t-SNE and UMAP in the retrieval github project
   and the results are in the images subdirectory here.

   Because these embedding will be used for retrieval, these charateristics
   in the UMAP, and t-SNE plots can help interpret results (along with the
   metrics in post training analysis).

   Expected results:
      well fit:
         the expected results when have enough features in both the Query
         and Candidate models is that the L2 normalized embeddings will
         evenly fill their hyperspheres in the maps and that the individual 
         movie tiers will be co-spatial with one another, and the same for 
         user_tiers.
         expect  L_unif=-2.75 to -2.8 where L_unif is hypershpere
                 uniformity from Wang & Isola, 2020
      under fit:
         all points lie in an outside ring because there are not enough dimensions 
         to represent the features well without wrapping around the ring.
      over-fit:
         points are clustered, highly fractured and separated  and the tiers
         are not co-spatial

   Note that I ran models to see those features by using HPO on fixed layer_sizes
   from layer_size=[8,4] and doubling that all the way up to [258,128] to see
   the under fit to over fit evolution.  Then to more properly compare that evolution,
   I fixed the hyperparameters to the best for the under-fit range and then ran the
   pipeline for fixe layer_sizes [8,3] through [256,128] again.
   The results are stored as multi_model_comparison directory.

   The best fits show that the embeddings evely fill their hypershperes with the
   caveat that one clan see that the Movie features of id and genres are not
   enough.  (easy to add the movie release year, title, and additional info 
   such as actors and directors, etc.)


How large should num_candidates found from an approx nearest 
neighbor search of user embeddings who rated tail movies?
This can be done as post-data analysis of the trained 
TwoTowerDNN models (in the retrieval stage).
The common advice is that num_candidates should be 10x to 100x
the final top_k=20 that end-to-end inference will produce.

To make training and inference more feasible for this project,
I settled on num_candidates=100 and top_k=20.
